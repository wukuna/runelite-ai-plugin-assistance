# Integrations and shared state

Identify the exact deployed provider commit and supported public contract before relying on it. Source/fixture evidence and proposed maintainer protocols are labeled separately. See [runtime.md](runtime.md) for threads and image readiness, [policy.md](policy.md) for eligibility.

## Public integrations and file access

`PluginMessage` supplies namespace, name, and a data map; it does not define a discovery, image-loading, or reload protocol. Check the actual released provider and agree on the minimum contract before adding consumer-specific fields upstream. Prefer public services or messages carrying standard Java types across plugin classloaders. Treat Discord suggestions as design discussion unless a specific agreement or implementation is evidenced. [PluginMessage source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/events/PluginMessage.java).

For an asynchronous image integration, invalidate cached and pending results when the provider reports reload. A config change is not equivalent to a reload unless the provider's code guarantees it. A filename describes an asset; it does not, by itself, tell the consumer which icon was selected for a particular ground item.

`Filepath` provides rooted access; it does not grant an integration contract or unrestricted access to another plugin's files. A known filename, a loadable image, a resolved filter result, and permission for the access are separate questions. Use plugin-owned storage or explicit supported selection APIs and review `Unchecked` separately. See [Filepath source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/util/Filepath.java) and the specific Loot Filters review in [review-evidence.md](review-evidence.md#apis-and-packaging).

## Resolve display behavior, not just image names

Determine how manual hide/highlight overrides interact with filter rules in the released provider. The [language guide](https://github.com/riktenx/loot-filters/blob/userguide/filter-lang.md) distinguishes terminating rules from continuing apply blocks, hidden from hideOverlay, and File/Sprite/Item/CurrentItem icons. In [released DisplayConfig](https://github.com/riktenx/loot-filters/blob/993fd054e08d42a77d3415acbb9ac7c2797726ed/src/main/java/com/lootfilters/DisplayConfig.java), nullable booleans mean unset during merge; compact mode supplies a current-item icon; `getIcon()` alone does not enforce overlay visibility. Test visibility separately from image availability and menu color. Do not assume reading the saved script reproduces live resolved settings.

## Party integration supplement — verified 2026-11-02

- **Observed review:** [RaidParty #19086](https://github.com/runelite/plugin-hub/pull/19086#issuecomment-6445556126) was asked to update for new core party changes. The PR was closed unmerged when checked. This establishes a compatibility requirement, not a blanket rejection or approval of its proposed raid/defense features.
- **Verified 1.13.5 API:** [PartyDataService](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/party/PartyDataService.java) exposes per-plugin subscriptions for core party fields and skills; [PartyMember](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/party/PartyMember.java) exposes received data. Prefer this public integration over duplicating inventory/equipment/prayer arrays in a custom protocol. Subscription masks combine across plugins: removing one plugin's subscription does not promise another plugin stops sharing the same field. Unsubscribe only registrations owned by the current plugin on shutdown; do not leave the shared party as a side effect.
- **Verified transport behavior:** [WSClient](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/party/WSClient.java) identifies custom message classes by simple class name and posts received events from its socket callback path. Use distinct class names, validate membership/payload/context, and marshal mutable plugin state to its owner. Test late-join baselines and reconnect with actual peers; API presence alone does not verify edge cases.
- **Compile-verified API boundary, 2026-11-02:** `WSClient.isOpen()` is package-private and `PartyService` has no public `getMemberId()` in 1.13.5. Use the public local-member contract and its member ID; do not access private transport state. `PartyService.send` owns its native connection recovery, so a local-member check is not proof that the socket is currently open. Do not add a separate auto-rejoin loop. `DrawManager` is in `net.runelite.client.ui`; prefer `ImageCapture.saveScreenshot` over the deprecated upload-style overload for local captures. These were verified against the 1.13.5 JAR/source during integration compilation, not through live gameplay.
- **Historical author report:** [RaidParty #13890](https://github.com/runelite/plugin-hub/pull/13890) describes prior disablement for excessive party traffic and subsequent delta/throttle fixes. Treat its numbers as author-reported, not local benchmarks. Bound custom message rates, baseline responses, and queues; do not claim this historical snapshot describes the currently distributed source without checking its pinned revision.

## Shared state across profiles and clients

Shared jars update every local profile using them; profiles do not provide independent binary versions. Preserve any intentional local-test descriptor/configName isolation and existing feature groups. Verify runtime-loaded identity separately from filenames. Do not replace locked jars or infer successful activation merely from compilation.

Profile copies must preserve explicitly excluded window sizes/layouts, and verify that the chosen source actually contains the intended settings before overwriting targets. A descriptive profile name alone does not establish its contents. Close clients before file-level edits so they cannot write stale state back. Cloud sync can overwrite local-only edits; use only the specifically authorized official session/API scope and retain backups. Do not treat previous approval for one transfer as general credential permission.

Shared badge persistence must merge concurrent observations under a cross-client lock and retain atomic replacement and bounded recovery. An optimization that skips parsing unchanged contents must still read/close the file, notice another client's changes, and merge pending local observations. Size/mtime alone is not a guaranteed content revision. Do not suppress cross-client changes with an indefinite in-memory cache.

Saved desired chat visibility differs from temporary runtime ownership. Persist the user's hidden-chatbox choice in the plugin's own profile group and restore it after login/restart and after a competing chat plugin releases control. Temporary restoration for compatibility must not overwrite the saved choice. Use generation checks for queued refreshes; never alter the competing plugin's settings.

For external-chat integrations, input routing, incoming-message isolation, provider enabled state and a single active reader are independent behaviors. Validate each one and preserve the project's public/local boundary. Documentation saying an integration is in progress does not establish that its API is released.

## Resource packs

When supporting resource packs, respect widget-specific and global sprite overrides and the user's selected artwork. Detect changed SpritePixels identity and do not cache a fallback indefinitely while images are still loading. Converting an in-memory sprite to BufferedImage does not itself hold the source PNG open.

A Windows FileSystemException during pack-directory deletion establishes a failed cleanup operation, not which process owns the handle or the cause of all switching delays. Another handle in the same process can cause the same wording. Inspect the actual Resource Packs revision and handle/process evidence before assigning responsibility. Example implementation: [PacksManager at a recorded revision](https://github.com/melkypie/resource-packs/blob/79ce581260732811481f0066836317f8ab5764fc/src/main/java/melky/resourcepacks/features/packs/PacksManager.java).

If changing the provider's cache management, investigate serialized refresh work per cache root, multi-client coordination, versioned replacement after readers release files, and bounded background retry. Close image readers, streams, directory walkers and ZIP/output streams on every exception path. Do not delete active caches or add pack-management responsibilities to an unrelated overlay to compensate.

Inventory Setups source `16f2c0a319672c2e19738276a17de63aea7216fa` opens native Bank Tags views through BankTagsService. A compact-search implementation can target the native SEARCH/SEARCH_GRAPHIC widgets without modifying a separate Swing viewer or provider configuration. Compatibility still needs live checks.
