# Runtime, threads and lifecycle

Version-specific source evidence spans 1.13.3–1.13.6 and is dated below. The recorded fixtures used Java 11; select the target version from the current project and Hub requirements. Recheck affected APIs when changing dependency. These are engineering facts, not additional Hub policy.

## Start with the actual runtime

RuneLite plugins are Java running inside a shared JVM. Swing panels, game widgets, client scripts, and background tasks have different execution contexts. `JavaScriptCallback` is a Java interface implementing a widget/script callback; its name does not mean a JavaScript interpreter is available. Web/Node event-loop assumptions do not establish Java thread safety. See [JavaScriptCallback source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-api/src/main/java/net/runelite/api/widgets/JavaScriptCallback.java) and the [Plugin Hub development setup](https://github.com/runelite/plugin-hub#setting-up-the-development-environment).

Before proposing an integration, identify the exact dependency, provider version, deployed source hash, and existing public service/message/config interfaces. A field inside a provider's private model is not automatically exposed to other plugins. A local paired test does not demonstrate compatibility with the ordinary released provider.

## Thread ownership and script reentrancy

- `PluginManager.startPlugin` and `stopPlugin` assert Swing EDT execution and call plugin lifecycle methods there. Lifecycle hooks are not automatically client-thread callbacks. [PluginManager source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/plugins/PluginManager.java).
- `EventBus.post` invokes subscribers synchronously on the posting thread. It sorts by descending priority, then subscriber class name for ties. `@Subscribe` alone does not marshal an event. Inspect each event's producer, especially configuration/profile changes. [EventBus source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/eventbus/EventBus.java).
- Verified 2026-10-31 on 1.13.4: `EventBus.register` rejects an annotated method unless its name is exactly `on` plus the event class's simple name. Two handlers for one event at different priorities should use separate subscriber objects (or the supported programmatic registration API), with explicit lifecycle cleanup. Improved Right-Clicks failed to enable because `onMenuThemeRender(BeforeMenuRender)` violated this rule. Exercise the real event bus and plugin registration in lifecycle tests; mocked registration and direct handler calls miss this failure. [Version-matched registration checks](https://github.com/runelite/runelite/blob/runelite-parent-1.13.4/runelite-client/src/main/java/net/runelite/client/eventbus/EventBus.java).
- `ClientThread.invoke` may execute immediately when already on the client thread. `invokeLater` defers execution. Returning `false` from a queued `BooleanSupplier` requests another attempt; include a valid lifecycle/context and a terminating condition when waiting for something that may never arrive. [ClientThread source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/callback/ClientThread.java).
- `Client.runScript` is client-thread-only and non-reentrant. Trace indirect calls: `Quest.getState` invokes a script, and `BankSearch.layoutBank` runs the bank widget's inventory-transmit listener. Calling those helpers inside a script callback can be unsafe even without a direct `runScript` call at the call site. Defer the script work until the current script returns, or snapshot the needed result from an appropriate event. [Client contract](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-api/src/main/java/net/runelite/api/Client.java), [Quest source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-api/src/main/java/net/runelite/api/Quest.java), [BankSearch source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/plugins/bank/BankSearch.java).

Swing component mutations normally belong on EDT; long jobs there freeze the UI. Snapshot game data on client, do pure expensive work off client, then publish on the owning thread after checking that the request is still current. Non-async `CompletableFuture` continuations can execute on the completing thread; default async methods normally use the common pool. Neither guarantees client thread or EDT. Do not wait for dependent work with `join/get` in a client callback. A completed `SwingWorker.get()` in `done()` is a different case. [Swing EDT guidance](https://docs.oracle.com/javase/tutorial/uiswing/concurrency/dispatch.html), [Java 11 CompletableFuture contract](https://docs.oracle.com/en/java/javase/11/docs/api/java.base/java/util/concurrent/CompletableFuture.html).

## Positioned overlay routing

Verified 2026-11-02 on RuneLite 1.13.5: `OverlayManager.rebuildOverlayLayers` promotes a non-widget `UNDER_WIDGETS` overlay to `ABOVE_WIDGETS` when it has a preferred location and no preferred snap position. Test routing with the real manager after dragging, loading positions and switching profiles; checking `Overlay.getLayer()` alone misses the promotion. `ABOVE_SCENE` remains below interfaces but also below overheads, and fixed-mode rendering is clipped to the viewport. Choose that layer when this ordering fits the overlay, rather than changing core anchors or hiding game widgets. A visually covered history overlay also needs to release wheel input, using client-thread snapshots rather than widget access from AWT. [Version-matched manager](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/ui/overlay/OverlayManager.java), [renderer](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/ui/overlay/OverlayRenderer.java).

## Images have identity, readiness, and ownership

`ItemManager.getImage` returns an `AsyncBufferedImage`, which can exist before its pixels are ready. Its loader retries when the game cannot yet create the sprite. `onLoaded` calls listeners when ready; registration after readiness queues the callback through `ClientThread.invokeLater`. The general `loaded()` implementation runs listeners on its caller's thread, so marshal consumer work explicitly where needed. [ItemManager source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/game/ItemManager.java), [AsyncBufferedImage source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/util/AsyncBufferedImage.java).

For screenshots, retain immutable positions/styles, wait asynchronously for all required images, and bound cancellation/timeouts. A repaint callback alone cannot repair a file already saved with blank icons. For another plugin's image provider, establish request thread, completion thread, failure/missing-image behavior, shared-image ownership, and reload invalidation. Do not mutate cached shared images; copy before tinting.

## Banking, item states, and settings

`ItemManager.canonicalize` in 1.13.3 unwraps notes/placeholders and handles selected worn variants. It is not the generic charged/broken-equipment family map. `ItemVariationMapping` groups related IDs but does not certify identical capabilities. Preserve the raw ID/state before family expansion; separately decide whether an item is owned, usable, equivalent for this role, or a tradeable purchase needing repair/charging. Do not count placeholders as owned stock. [ItemManager source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/game/ItemManager.java), [ItemVariationMapping source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/game/ItemVariationMapping.java).

Asynchronous results must belong to the full search context, not just its text: account/profile, plugin lifecycle, active tab, guide/inventory choice, and relevant input revision. Do not expand a Bank Tags tab beyond its membership. In 1.13.3 `BankTagsPlugin` stores the active tag object and replaces it on `openTag`; checking the active name and instance detects tab replacement as well as name changes. This is a version-specific observation, not a guarantee for all future implementations. [BankTagsPlugin source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/plugins/banktags/BankTagsPlugin.java).

RuneLite config interfaces use JDK dynamic proxies with `ConfigInvocationHandler`. Exercise the real proxy path when changing config value types: a plain anonymous config stub does not reproduce proxy visibility/casting failures. Improved Banking previously failed through a package-private enum return type; the config value type was made public and a proxy regression added. Preserve configuration group/key identity across display-name changes. [ConfigManager source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/config/ConfigManager.java), [ConfigInvocationHandler source](https://github.com/runelite/runelite/blob/runelite-parent-1.13.3/runelite-client/src/main/java/net/runelite/client/config/ConfigInvocationHandler.java).

## Version-specific fixes

Verified 2026-11-03 on RuneLite 1.13.6: [ItemManager.getItemPrice](https://github.com/runelite/runelite/blob/runelite-parent-1.13.6/runelite-client/src/main/java/net/runelite/client/game/ItemManager.java) returns `long`; use long arithmetic and guard quantity multiplication against overflow. Its `search(String)` reads the existing in-memory price table rather than making a per-call HTTP request. Exercise multi-billion-gp quantities and missing prices in value calculations. Tests that need the package-private ConfigInvocationHandler cannot simply join `net.runelite.client.config`: the published RuneLite jar is signed, and an unsigned test class in that package fails signer checks. Keep any reflective test access in the test source set and verify it is absent from packaged production classes. This is a test-harness constraint, not an exception permitting reflection in shipped plugins.

Verified 2026-11-02 on RuneLite 1.13.5: `@PluginDependency` shares the provider's public Guice module and establishes loading order; it does not enable or start a disabled provider. A usable service reference is therefore not evidence that the provider's event callbacks are running. Improved Banking could open a Bank Tags preset while Bank Tags was off, producing incomplete item rows; the user confirmed enabling Bank Tags restored them. Check `PluginManager.isPluginActive`, guard asynchronous openings/reopens, and handle `PluginChanged` on its actual EDT producer thread by deferring owned widget/service cleanup to client. Retain lifecycle and request-generation checks across profile changes; do not silently write the provider's settings. [Version-matched PluginManager](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/plugins/PluginManager.java), [tested guard](https://github.com/wukuna/improved-banking/commit/39df10f041f53c31a05924f56a6df841d3527dd6), [Hub PR 19979](https://github.com/runelite/plugin-hub/pull/19979). The guard was tested automatically; user confirmation covers the original cause, not live execution of the new build.

Verified 2026-11-02 on RuneLite 1.13.5: `ConfigManager.sendConfig()` replaces its `ConfigProfile` reference through `updateProfile()` during ordinary background saves, and `ConfigProfile` does not override object equality. Comparing saved and current profile objects therefore falsely rejects long-running editor drafts and imports. Compare the stable `ConfigProfile.getId()` and retain lifecycle/generation checks plus relevant settings snapshots to reject real switches and conflicting edits. Improved Looting reproduced this when importing custom sounds for tiers 1 and 4, and also used the same faulty check for setup review/apply and asynchronous filter loading. [Version-matched ConfigManager](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/config/ConfigManager.java), [ConfigProfile](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-client/src/main/java/net/runelite/client/config/ConfigProfile.java), [tested fix](https://github.com/wukuna/improved-looting/commit/ddd35dcd26df23240956f0d19af515c2761fa7e4), [Hub PR 19972](https://github.com/runelite/plugin-hub/pull/19972). Regression tests distinguish replacement objects with the same ID from actual profile changes and verify setup transfer/Undo. This is engineering evidence, not a claim of live verification or maintainer acceptance.

Verified 2026-11-02 on RuneLite 1.13.5: a MouseWheelListener calling Widget.isHidden() through an overlay visibility helper threw "must be called on client thread" and prevented camera zoom even over the game world. The failure only appeared with native chat open and scroll history enabled; minimized chat and an open menu short-circuited the failing path. Publish visibility/menu eligibility on the client/render thread, and let AWT wheel callbacks read snapshots and painted bounds only. Test wheel dispatch on Swing EDT and verify it makes no Client or Widget calls. Engineering fix and regression coverage: [Improved Chat source change](https://github.com/wukuna/improved-chat-and-overlays/commit/50065038050b3194dbb6a17d080c67379b334e37), [Hub PR 19964](https://github.com/runelite/plugin-hub/pull/19964). This is an observed runtime defect and tested fix, not a claim of live gameplay verification or maintainer approval.

Verified 2026-11-01: Hub `runelite.version` advanced to 1.13.5. That API removes `FriendsChatChanged`; [FriendsChatSync](https://github.com/runelite/runelite/blob/runelite-parent-1.13.5/runelite-api/src/main/java/net/runelite/api/events/FriendsChatSync.java) reports full joins/resyncs/leaves. Do not rely on an offline `latest.release` build to establish current Hub compatibility. Improved Chat's channel-name history now reads the initialized FriendsChatManager on GameTick, retaining compatibility with 1.13.4 as well and handling a temporarily absent manager. Check the event producer/contract before migrating other subscribers.


## Immediate sidebar settings

Update only the property being edited. Applying the entire stale form from one checkbox or arrangement change can overwrite newer settings, selections or pending text. Guard programmatic refresh listeners, preserve in-progress text/spinner edits, and commit text through its normal Enter/focus-loss behavior. For an immediate-settings UI, apply ordinary controls as selected; keep deliberate batch operations such as import, template application, reset and Undo explicit. Follow the product's intended interaction rather than imposing one pattern on every editor.
